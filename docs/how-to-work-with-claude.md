# როგორ ვთხოვო Claude-ს ამ პროექტში

შენ კოდს არ წერ — პრომპტს წერ. ეს ფაილი იმაზეა, როგორ ითხოვო ისე, რომ პასუხი პირველივე
ცდაზე სწორი იყოს.

## ძირითადი წესი

აღწერე **რა გინდა რომ მოხდეს**, არა **როგორ გავაკეთო**.

| ნაცვლად ამისა | თქვი ეს |
| --- | --- |
| „შეცვალე `hotkey.py`-ში threshold" | „ძალიან სწრაფად ჩერდება ჩაწერა, ცოტა მეტხანს დაელოდოს" |
| „დაამატე try/except transcriber-ში" | „როცა ინტერნეტი წყდება, პროგრამა კვდება — არ უნდა კვდებოდეს" |
| „refactor app.py" | არაფერი. თუ მუშაობს, არ შეეხო |

## კარგი პრომპტის მაგალითები

- „F9 ვერ ვამჩნევ რომ მუშაობს — რაღაც ნიშანი მინდა ეკრანზე რომ იწერს"
- „ტექსტი ჩნდება, მაგრამ ბოლოში ზედმეტი წერტილი აქვს — მოაშორე"
- „მინდა რომ Windows-ის ჩართვისას ავტომატურად ჩაირთოს"
- „ღილაკი შეცვალე F9-დან მარჯვენა Ctrl-ზე"
- „რამდენი დამიჯდა დღემდე?"

## რას ნიშნავს „შემოწმება"

ყოველი ცვლილების შემდეგ Claude გეტყვის ოთხ რამეს: **სად** დავაჭირო, **რა** უნდა
დავინახო, **რა** ნიშნავს რომ იმუშავა და **რა** ნიშნავს რომ არა. თუ ეს ოთხი არ ითქვა —
სამუშაო დასრულებული არაა, კითხე.

ამ პროექტში შემოწმება თითქმის ყოველთვის ასე გამოიყურება:

1. გახსენი Notepad
2. დააჭირე F9-ს, თქვი ქართული წინადადება, გაუშვი
3. ტექსტი უნდა გამოჩნდეს კურსორთან 2-4 წამში

## როცა რაღაც გაფუჭდება

სამი ფრაზა საკმარისია:

- **„გააუქმე ბოლო ცვლილება"** — ბოლო save point-ზე დაბრუნება
- **„რაღაც გაფუჭდა, გაასწორე"** — Claude თვითონ იპოვის რა შეცვალა და გაასწორებს
- **„დააბრუნე ბოლო მომუშავე ვერსია"** — ყველა save point-ს გაჩვენებს, შენ აირჩევ

არაფერი იკარგება — ყოველი მნიშვნელოვანი ცვლილების წინ save point იქმნება.

## რა უნდა თქვა უცილობლად

- **„ეს დიდი ცვლილებაა?"** — თუ არ ხარ დარწმუნებული რას აპირებს Claude
- **„ჯერ მაჩვენე რას აპირებ"** — თუ გინდა ჯერ გეგმა ნახო, მერე შესრულება
- **„გაჩერდი"** — ნებისმიერ მომენტში

## რაზე არასოდეს გკითხავს Claude

`.env` ფაილს Claude არ წერს. თუ API გასაღები უნდა შეიცვალოს, Claude მოგცემს ხაზს და შენ
ჩასვამ. გასაღების მნიშვნელობას პასუხში არასოდეს დაწერს — შემოწმებაც კი მხოლოდ
„დაყენებულია / არაა" ფორმით ხდება.
